# 悬浮采集器配置与页面能力交接

悬浮窗负责选页、右键标注、保存，以及复制本页任务。它不记录网页事件序列，不自动绑定或打开 ZCode 会话，不调用模型。技能以文件交付，不默认安装到 Agent 用户目录，不修改默认模型。

版本先核对：已发布稳定版 **v0.1.0 仅支持单卡流程**；同页任务包与“复制本页任务”属于 **v0.1.1 未发布开发版**。不能把开发分支、构建成功或旧版验收写成新版 UI 已验证。

## 按需读取

- 配置或排查连接：读 [configuration.md](references/configuration.md)。固定浏览器、身份与定位语义沿用 [cdp-page-contract](../cdp-page-contract/SKILL.md)；只有配置任务时不执行网页业务。
- 整理一组控件：读 [handoff.md](references/handoff.md)，再读用户指定的 `page-bundles/page-.../task.md` 和 `page-bundle.json`。以任务包中完整脱敏卡片及其来源为范围，不扫描其他页面或整浏览器。
- 兼容单卡：用户给的是 `captures/cap-.../task.md` 时，读取同目录 `capture.json`、`description.md`，仍按单卡整理，不要求先升级或转包。

## 从标注到现有可见会话

用户在同一页保存多张控件卡后，在开发版悬浮窗点击“复制本页任务”，把复制到的 `shortTask` 粘贴进已有、可见的 ZCode 对话。接收方需要真实读取本地任务文件；仅出现路径不代表文件内容已进入模型。

多个控件共同描述页面能力，例如输入区、查询入口和结果区；**保存顺序不等于操作顺序**。只有用户用途或页面约定足够支持的关系才可编写为候选步骤，缺少的流程信息写为待确认。

## 操作边界

- 使用指定的固定 Chrome 和 profile；人先登录，工具复用仍有效的会话。不换新 profile、无痕窗口或后台接口替代这条前端路线。
- 普通主 frame 中的 DOM/AX 信息和 locator 是定位观察；用户描述提供业务含义，二者不能互相替代。同页分组不意味着控件属于同一条业务记录。
- 整理只生成当前任务目录 `generated/` 中的统一 skill、页面约定和候选 runner。**不连接网页、不执行 runner、不提交真实业务动作**，不自动安装生成技能。
- 配置在按需打开的设置入口完成，排错读取指定工作区 `.logs/picker.log` 的必要部分；不将大日志面板或模型启动器塞回悬浮窗。
- CLI 仅在用户明确要求时调用。`-p` 发起独立任务，`--cwd` 指定采集工作区；这不会绑定当前 UI 对话，也不保证结果自动出现在可见会话。不能据此推断 CLI 和 UI 一定使用不同数据库。

## 输出与证据

草稿保留每张卡的来源与业务范围，核对参数、前后条件及未知项。定位高亮、CLI 退出码、生成文件分别只证明定位、进程结果或产物存在；不能宣称业务能力已验证。

结束时报告使用的页面任务包或单卡、包含控件数、生成文件、实际检查和待验证项。CLI 结果不明时保留运行记录，不自动重发。新版 UI 本轮尚未验收：新 EXE 的自动启动检查被自动审批以 `blocked by policy` 拒绝，不能记成已成功启动。

短任务：`读取“指定 task.md 的完整路径”，按其中说明整理能力草稿。`
