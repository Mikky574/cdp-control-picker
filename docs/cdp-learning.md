# 你写用途，ZCode自己核对怎样使用

0.3.1新策略不再让人给控件勾选“读取 / 点击 / 填写”。你说明这个位置做什么、什么时候用、希望看到什么，ZCode结合真实页面判断可用的动作，并用结果证明哪些步骤跑通。

## 人需要做的事

在已登录专用Chrome里选页，右键控件并保存名称与用途。主窗每项一行，点“编辑”看完整名称、说明、前置条件和预期结果；“⋯”可删除或调整顺序。需要先后时勾选“按此顺序操作”，它表示你的意图，不表示已经执行过。

首次按部署说明连接“网页能力学习”原生扩展，由你在ZCode批准会话写入/完全访问。连接会报告固定学习项目；资料可放独立长期目录，或“使用 ZCode 学习空间”对齐。模型列表与同一桌面同源，每次会话输入使用精确选择，不改全局默认或凭据。

点击“交给 ZCode 学习”后，在持久发送区看进度和公开回执。你可以在同一ZCode对话继续补参数或纠正理解，不需要管理内部交接编号。

## AI怎样决定动作

1. 读取完整控件包、用途、条件、顺序与学习技能。
2. 连接本次实际Chrome和明确页签，核对页面路由以及控件类型、唯一性、可见和可用状态。
3. 结合用途判断读取、填写和点击等步骤，自行寻找适用样本或准备隔离测试数据。
4. 执行、回读，修好能解决的问题再测。记录真实页面和隔离测试分别通过了什么，保存可复用技能与调用步骤。

新包的infer-from-purpose策略中，旧allowedActions不再是权限开关；输入框或按钮类型也不等于已经知道业务效果。填写可能自动保存，名字叫“查询”也不保证只读；涉及真实提交/删除/付款时仍按你的具体任务处理。

## 连接不是一个地址

Chrome的CDP地址用于找浏览器，页签ID由Chrome返回，selector来自网页位置。context.md是本地说明；handoff编号只追踪发送，原生sessionId用来继续ZCode对话，这些身份不能互换。

默认由ZCode Extension Host的owner创建、发送和广播原生会话；受理后立即请求打开同一会话，等待精确操作。原生学习项目与资料目录可能不同，任务绝对引用实际资料。CLI仍可兼容诊断，但不是原生导航/实时消息的替代。

## 怎样判断学会了

“连上了”“找到控件”“流程成功”分别记录。只知道两个selector或点击已派发都不够，实际页面结果必须支持结论。learning/保留报告、页面约定、技能、参数化步骤与工具回执；未验证项保持明确。

旧context-only仍只接收；旧学习包没有新策略时继续原allowedActions语义。本RC源码、真实HTTP协议联立与成品检查通过；Host为模拟，原生安装/授权、导航与GUI实时消息留待目标机验收；旧CLI候选的真实模型结果只作兼容路线证据，不能移作新路成功。本轮分层结果见[验证记录](cdp-picker-validation.md)。
