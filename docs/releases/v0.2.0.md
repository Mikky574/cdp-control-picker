# v0.2.0：把控件上下文交给 ZCode

**最新上下文首轮已实测通过：完整读取、简短确认并等待用户。完整120项单元测试与最新EXE资源/归档检查通过。**

## 使用行为

- 固定专用 Chrome 内右键保存控件名称、定位与用途，同页可标注多张卡。
- 点击“发给 ZCode”，发送当前页已保存标注的完整脱敏合集。
- ZCode 首轮读取完整资料、简短确认，然后等待用户。后续信息和工作由用户在 ZCode 对话中自行提出。
- “复制交接说明”只复制读取context.md的短任务，供人粘贴，不自动发送。

采集器首轮不生成技能、页面约定、脚本或其他能力文件，不规划后续，不连接网站或执行业务。用户以后可自行在ZCode要求生成/使用技能，不把它设为采集器默认流程。context.md 是当前交接入口，旧 task.md/generation/generated 仅兼容保留，不作为首轮要求。

## 后台机制

app-server stdio + 本工具选定工作区/会话yolo完全访问继续保留，参考Plaza runtime、真实SID与事件订阅。协议ACK是受理，要等本轮终态与模型确认；模型回复、私有索引登记和GUI可见分开核实。后台不依赖桌面焦点，不改其他项目、全局模型/认证或Plaza角色。

私有索引适配不是官方公开同步API。先核对真实会话与版本/schema，备份后窄范围登记；本工具ownership、同SID/taskPath匹配旧行才可只改mode，外来任务及其他列不动。相同标注已有对话直接复用，不重新交接；结果不明不重发，索引失败只补登记。
