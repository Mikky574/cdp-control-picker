# v0.2.3候选：单行控件与持续发送反馈

当前为单行候选，尚未发布。本版默认约280dip宽，恢复分层清楚的浏览器入口，发送结果单独保留。v0.2.2及更早发布说明保持为历史。

- 顶部按“启动 Chrome / 刷新 / 记录 / 日志”→选页→“连接并开启采集 / 关闭”排列；设置按需打开。
- 每个控件只占一行：序号、名称、“编辑”和“⋯”。名称按实际字体测量尾部省略，完整名称、用途、动作及条件只在编辑弹窗查看；“⋯”菜单提供上移、下移和删除。有限视口内滚动查看更多。
- 独立发送区显示准备、处理中、用时与不定进度、完成、已发过、失败、未知和待补登记；不会被浏览器刷新提示覆盖。
- “查看发送回执”提供控件数量、对话名、记录时间和公开回复摘要。摘要不是内部思考，也不代替ZCode完整对话。
- 同份成功或未知内容在UI层禁发；修改标注、删除后集合或顺序后按新内容交接。快速重复立即显示已有回执，不假装等待；登记失败只补登记。
- “启动 Chrome”按指定CDP监听端口的真实进程匹配窗口，恢复最小化并尝试前置，回读实际前台结果。系统拒绝或无窗口时明确提示，不切到其他Chrome、不重启共享浏览器。
- 次按钮恢复“复制交接说明”，只复制短任务，不提交模型。

UI缓存是反馈与前置门禁；后台原有OS工作区锁、内容指纹和交接日志继续防止重复模型提交。页面包、软删除快照和声明顺序语义不变，首轮只读取完整上下文、简短确认并等待用户，不生成技能、脚本或后续计划，不操作网站。
