CDP 控件采集器 v0.2.0 · 开发候选说明（未发布）

“整理本页标注（ZCode）”会把当前页已经保存的控件位置、用途和预期结果汇成统一能力草稿。
主路径为 app-server stdio + 用户授权的本任务 yolo + 桌面私有索引登记。
后台原 SID 续聊、Bash 校验与 owned 索引 mode 更新已有实测；GUI 已打开原历史，桌面同会话续聊已完成可见回复；最新 EXE 重新启动与最终整包仍待验收。

使用路线
1. 启动或复用固定专用 Chrome，由本人登录网站。
2. 刷新并明确选页，连接后分别右键标注控件，填写用途、允许动作、预期结果后保存。
3. 点击“整理本页标注（ZCode）”，生成包含完整脱敏卡与来源的同页页面包。
4. 后台 app-server 建立真实 sessionId，订阅进度并单次提交任务；ACK 只是受理，继续等实际终态和最终快照。
5. 完成后兼容登记桌面项目/任务索引；请到对应项目核对同一个 SID，打开原会话继续。

用户已明确授权采集器任务 yolo 完全访问，可做格式、引用与语法检查。
当前任务仍只生成 draft，不连接网站、不执行业务、不运行生成的 runner、不自动安装技能。
不额外禁用工具；未执行的检查如实记录。此设置不改全局默认、模型认证或其他 Plaza 角色。
启动、刷新和采集不调用模型，后台不依赖桌面焦点；悬浮窗没有续聊输入框。
CLI -p runner 保留为源码 fallback，主按钮使用 app-server。

当前安装目标为 ZCode 3.16.3.8992 / 内置 CLI 0.17.0，不保证其他版本。
目标电脑需已有 Chrome 与 ZCode，最终便携包无需另装 Python 或 Node。

私有索引登记不是官方公开同步 API。先核对版本/schema与真实会话，写入前备份 .handoffs/index-backups/。
仅 owned-marker、同 SID/taskPath 匹配的本工具旧行允许只改 mode；外来任务和其他列不动。
registered/indexRegistered 仅证明登记，不表示 GUI 可见已验证。
结果未知保留 SID 不重发；任务完成而登记失败时，相同内容重试仅补登记，不再调用模型。

默认记录目录为 CDP-Picker-Workspace，专用浏览器资料为 CDP-Chrome-Profile；源码默认数据在 .local/。
captures/ 兼容单卡，page-bundles/ 保存同页合集，generated/ 是草稿，.handoffs/ 保存请求、SID、结果与回执。
个人资料、凭据、完整会话、日志及索引备份留本地，不进入 Git/Release。设置仅本次运行生效。
