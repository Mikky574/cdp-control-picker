# ZCode 实际接收什么

核对日期：2026-11-26。稳定版为 v0.1.0；页面汇总与悬浮窗属于尚未发布的开发版。

## 稳定版是一次一个控件

稳定版的记录列表只能选一张卡。“发送所选控件”读取这张卡的 `taskPath`，另起一个 ZCode CLI 任务，最初只给一句“读取这个 task.md，按其中说明整理能力草稿”。

ZCode 需要通过自己的文件工具读取任务，再读取该卡的 `capture.json`、`description.md` 与引用技能，才能看到定位信息和人的用途说明。路径出现在消息中，不等于文件正文已被模型读取。

此版本没有合并其他卡片，没有把整个网页发送给模型，也没有录制全部点击、输入或网站事件处理器。网页浮层监听右键是为了选定控件、填写标注；保存结果是“控件定位＋业务说明”，不是页面事件录像。

## 页面汇总的目标

按用户确认的方式，将同一页面已经右键标注的多张卡组成一份页面任务：

| 文件 | 内容 |
|---|---|
| `page-bundle.json` | 页面身份、已标注控件集合、每张来源卡与用途、候选定位、草稿状态 |
| `task.md` | 读取规则、技能引用、统一页面能力的输出要求 |
| `generated/` | 该页面的能力 skill、页面约定和候选 runner |

按页面 origin 与 path 分组，忽略查询串和片段；不同网站或不同路径不混在一起。每张原卡保留，不因导出而修改。多个控件的操作顺序若没有依据，应标为待验证，不能仅凭它们位于同页就编造完整业务流程。

悬浮窗中的“复制本页任务”负责导出和复制短任务。用户将短任务贴到已有 ZCode 会话，就在那个可见会话中继续整理；程序本身不宣称已发送给模型。

## 为什么界面里没看到对话

稳定版用 CLI 的单次 prompt 模式创建新任务，工作目录是采集器选择的记录工作区。它没有绑定用户正在看的 ZCode 对话，也没有传入那个对话的会话标识或向界面发送消息。

CLI 会话可能持久化。桌面端也有发现工作区会话的机制，因此不能直接说 CLI 会话永远不会出现在界面里；但这不等于一次外部 CLI 调用会自动进入当前项目、刷新列表或打开对应对话。当前采集器没有实现这些界面衔接。

要实现自动可见，需要真正对接 ZCode 界面的项目、会话创建与事件展示入口，并拿到可核对的会话标识。另起一个 app-server 或获得一个 CLI sessionId，单独都不能证明已进入当前界面。

如果 CLI 在创建会话前就启动失败，可能连新会话都没有；若任务启动后在工具权限处被拒绝，则需按实际 sessionId 和日志判断。启动成功、生成文件、任务结束与界面可见是不同的检查项。
